# Project agent roles

The files in `.claude/agents/` are project-local subagent definitions for Claude Code.
Eight are pinned copies from Agency Agents; one comes from the Loop Engineering scaffold.

## Selected roles

Only roles that match this repository (a Python standard-library server, SQLite, native
JavaScript client, and a backlog about terms, projects, invoices, reports and backup)
were installed.

| Role (`name:`) | Upstream path | Tools here | Use it for |
| --- | --- | --- | --- |
| Software Architect | `engineering/engineering-software-architect.md` | `Read, Grep, Glob` | Reviewing a design or ticket against `docs/architecture.md` before work starts |
| Codebase Onboarding Engineer | `engineering/engineering-codebase-onboarding-engineer.md` | `Read, Grep, Glob` | Tracing a code path and stating facts with citations |
| Code Reviewer | `engineering/engineering-code-reviewer.md` | `Read, Grep, Glob` | Reviewing a diff for correctness, security and maintainability |
| Reality Checker | `testing/testing-reality-checker.md` | `Read, Grep, Glob` | Checking that the evidence listed in `CLAUDE.md` really supports "done" |
| Accessibility Auditor | `testing/testing-accessibility-auditor.md` | `Read, Grep, Glob` | Reviewing keyboard, focus and labelling in `workbench/static/` (every ticket has keyboard criteria) |
| Backend Architect | `engineering/engineering-backend-architect.md` | inherited | Implementing server, command and schema work |
| Frontend Developer | `engineering/engineering-frontend-developer.md` | inherited | Implementing views in `workbench/static/js/` |
| Database Reliability Engineer | `engineering/engineering-database-reliability-engineer.md` | inherited | Schema upgrades, backup and restore (#2, #5, #17) |

The five reviewer roles are read-only: the only local change is one added frontmatter
line, `tools: Read, Grep, Glob`. The three implementation roles are byte-identical to
upstream and inherit the session's tools. Upstream definitions have no `tools` field.

`loop-verifier` (`.claude/agents/loop-verifier.md`) was generated by
`@cobusgreyling/loop@0.2.0` (MIT) and is limited here to `Read, Grep, Glob, Bash`: it has
no editing tools, but `Bash` can still write files, so it is restricted by instruction
rather than by tooling. It is only used from L2 onwards; see [LOOP.md](../LOOP.md).

The upstream role texts are general. Where a role's text mentions frameworks, cloud
services or scale that this project does not have, the rules in
[CLAUDE.md](../CLAUDE.md) win: standard library only, local only, no build step.

## Name collisions with user-level agents

A user-level `~/.claude/agents/` folder may already contain Agency Agents with the same
`name:` values (it did on the machine where this was set up). Claude Code resolves a name
collision in favour of the project-level file, so inside this repository `Code Reviewer`
and the other four reviewer names resolve to the read-only project copies. The upstream
names were kept unchanged on purpose: the copies stay comparable with upstream and an
update is a plain re-fetch at a new pin.

Consequences to know about:

- In this repository the reviewer roles cannot edit files or run commands even if the
  user-level copy can. To let a reviewer run tests, change its `tools:` line in a
  reviewed pull request; do not work around it.
- Outside this repository nothing changes.
- Agent definitions are read when a session starts. A session that was already open
  when these files appeared or changed keeps the list it started with, so it may still
  show the user-level copies with all tools. Start a fresh session from the repository
  root and repeat the load check below before relying on the read-only limit.
- User-level agents with other names remain available here as usual.

## Load check

Verified on 2026-11-21 with Claude Code 2.1.323, from the repository root of a checkout
of this branch:

```sh
claude -p --model haiku --max-turns 4 "List the subagent types available to you named Software Architect, Code Reviewer, Codebase Onboarding Engineer, Reality Checker, Accessibility Auditor, Backend Architect, Frontend Developer, Database Reliability Engineer and loop-verifier, with the tools shown for each. Then launch the Code Reviewer subagent and ask it to list the tools it can call."
```

Observed: all nine names were listed; the five reviewer roles showed
`(Tools: Read, Grep, Glob)`, the three implementation roles showed `(Tools: All tools)`,
and the launched `Code Reviewer` subagent reported exactly `Read, Grep, Glob`. That
confirms the project copies are loaded and take precedence over the user-level ones.
A second fresh headless run on 2026-11-22, after the `loop-verifier` tool limit was added,
listed the same nine names with the same limits, showed `loop-verifier` as
`(Tools: Read, Grep, Glob, Bash)`, and a launched `Reality Checker` reported exactly
`Read, Grep, Glob`.

`claude agents` in this CLI version manages background sessions and does not list agent
definitions, so the headless run above is the check to repeat after changing a role.

## Updating a role

1. Choose a new upstream revision and read the upstream diff and licence at that revision.
2. Re-fetch the file, re-apply the local changes (the `tools:` line for reviewer roles,
   the "Use proactively" sentence and the "In this repository" section, re-checked
   against the new upstream text), and update `agency-agents.lock.json` (revision, blob
   SHA, SHA-256).
3. Repeat the load check and record the result here.

## Local change: automatic delegation (2026-11-22)

One sentence beginning "Use proactively" was appended to the `description:` line of every Agency Agents role in `.claude/agents/` (not to `loop-verifier`). Claude Code uses that field to decide when to delegate, so the roles now run during ticket work without being named.

A section headed "In this repository" was also inserted directly after the frontmatter of every Agency Agents role (2026-11-22, again not in `loop-verifier`). It is project-specific text written for this repository, not upstream text: it names the files the role owns or reviews, the commands from `CLAUDE.md`, the invariants to check, the parts of the generic text that do not apply here and what the role must hand back. The upstream text below it is unchanged.

This supersedes any statement above that a role file is unmodified or that the `tools:` line is the only local change. To compare a role with the pinned upstream file, remove the "In this repository" section as well as the "Use proactively" sentence (and the `tools:` line where one was added) first.

The steps at which each role runs are in `.claude/skills/implement-ticket/SKILL.md`.

Verification, 2026-11-22 (Claude Code 2.1.323, fresh headless run from the root of this branch's worktree, after the sections were inserted): `claude -p "List every project subagent defined in .claude/agents with its exact name and tools, say for each whether its instructions begin with a section titled In this repository, and say whether a skill named implement-ticket is available. Plain list, no commentary." --model haiku` listed all nine roles by their exact names. The five reviewer roles showed `Read, Grep, Glob`, the three implementing roles showed all tools (no `tools` field) and `loop-verifier` showed `Read, Grep, Glob, Bash`. It reported the "In this repository" section as present at the start of all eight Agency Agents roles and absent from `loop-verifier`, and the `implement-ticket` skill as available. This run listed the definitions; it did not launch a role.
